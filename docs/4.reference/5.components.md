Every component here lives in the layer's `app/components/`. Nuxt resolves your
own file of the same name first, so replacing one is **creating** it — there is
nothing to eject and nothing to copy. What that costs you is in
[Override the theme](/guides/override-the-theme).

## Chrome

| Component            | Props            | What it is                                        |
| :------------------- | :--------------- | :------------------------------------------------ |
| `DuxtHeader`         | —                | The navbar: title, version badge, navigation, links |
| `DuxtSections`       | —                | The second navbar row, from `duxt.sections`         |
| `DuxtFooter`         | —                | Copyright, legal links, the "Powered by" line       |
| `DuxtSkipLink`       | —                | The first focusable element on every page           |
| `DuxtProgress`       | —                | The reading-progress indicator                      |
| `DuxtLocale`         | —                | The language switcher                               |
| `DuxtVersion`        | —                | The version switcher, from the manifest             |
| `DuxtVersionBanner`  | —                | What a reader in a non-default version is told      |
| `DuxtSearch`         | —                | The search dialog, opened with `⌘K`                 |
| `DuxtShortcuts`      | —                | The shortcut overlay, opened with `?`               |

## Navigation

| Component             | Props                        | What it is                                    |
| :-------------------- | :--------------------------- | :-------------------------------------------- |
| `DuxtNavigation`      | `items: ContentNavigationItem[]` | The sidebar tree                          |
| `DuxtNavigationLink`  | `item: ContentNavigationItem`    | One entry of it                           |
| `DuxtBreadcrumb`      | `path: string`               | The trail above the title                     |
| `DuxtToc`             | `links: TocLink[]`           | The table of contents                         |
| `DuxtPageNav`         | `path: string`               | Previous and next, bounded by the section      |

`DuxtPageNav` stops at the section boundary on purpose: crossing into another part
of the documentation is the section row's job, not that of a link reading "next".

## Page

| Component           | Props / events                            | What it is                                  |
| :------------------ | :---------------------------------------- | :------------------------------------------ |
| `DuxtPageInfo`      | `page`                                    | Edit link, last updated, contributors        |
| `DuxtCopyPage`      | `path`, `title?`, `rawbody?`              | Hand this page to a model, or read its source |
| `DuxtPageFeedback`  | emits `feedback: [helpful: boolean]`, default slot with `{ answered, answer }` | "Was this helpful?" |
| `DuxtCodeBlock`     | `code?`, `language?`, `filename?`         | The card around a code block                 |

`DuxtPageFeedback` carries no backend by design. Listen to the event, or take the
slot and render your own control — the layer stores nothing and calls nothing.
Wiring it to your own destination is a guide of its own:
[Collect page feedback](/guides/collect-page-feedback).

## Beyond components

| File                          | What replacing it does                        |
| :---------------------------- | :-------------------------------------------- |
| `app/layouts/docs.vue`        | The documentation layout                       |
| `app/layouts/default.vue`     | Everything else                                |
| `app/pages/index.vue`         | The landing page at `/`                        |
| `app/error.vue`               | The 404, including its nearest-page suggestion |
| `app/components/OgImage/Duxt.satori.vue` | The social card template            |

The shadcn-vue primitives under `app/components/ui/` are owned files too, but they
are not the public surface: they are the layer's building blocks, and a site that
needs a different one adds it with the shadcn CLI rather than shadowing ours.
