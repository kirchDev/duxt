::callout{type="danger" title="Never registered in a build"}
The panel exposes the resolved config, the file system paths behind it and a
button that deletes a cache directory. None of that is anybody business in
production, which is why the module returns before registering anything outside a
dev server.
::

## What it shows

The answer to the part of this layer that has been hardest to debug: what a
consumer writes is a compact list, and what the site serves is a set of
collections, prefixes, redirects, message catalogues and a download cache the
build computed from it.

Its panels show each of those as the running app has them, rather than as a
snapshot — sources, paths resolved step by step, pages, which version carries
which page, the build checks re-run, what the search index holds, the merged
config with the side of the merge each value came from, the locale keys against
the base, the content cache, and the redirects.
