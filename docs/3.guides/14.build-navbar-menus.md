An entry in `navigation` or `sections` becomes a menu when it has `children`.
Everything else is configuration on the same link objects: how deep the menu
goes, whether it is a list or a panel, and how each entry inside it is drawn.
The [demo](/demo) has one of each in its section row.

## Steps

::steps

1. **Nest the links.** An entry with `children` opens a dropdown, and a child
   with `children` opens a further menu beside it, as deep as the data goes:

   ```ts [app/app.config.ts]
   export default defineAppConfig({
     duxt: {
       navigation: [
         {
           label: 'Platform',
           icon: 'lucide:layers',
           children: [
             { label: 'Overview', to: '/platform' },
             {
               label: 'API',
               children: [
                 { label: 'REST', to: '/api/rest' },
                 { label: 'Webhooks', to: '/api/webhooks' }
               ]
             }
           ]
         }
       ]
     }
   });
   ```

2. **Make it a panel.** `menu: 'mega'` lays the children out on a grid of
   `columns`. A child with children of its own is a column under its name; a child
   without is a cell of its own:

   ```ts
   {
     label: 'Platform',
     menu: 'mega',
     columns: 3,
     divided: true,
     children: [
       {
         label: 'Highlights',
         hideLabel: true,
         children: [
           {
             label: 'Editor',
             to: '/editor',
             image: '/editor.svg',
             display: 'feature',
             description: 'Write and preview'
           }
         ]
       },
       {
         label: 'API',
         children: [
           { label: 'REST', to: '/api/rest' },
           { label: 'Webhooks', to: '/api/webhooks', badge: 'New' },
           { label: 'All of the API', to: '/api', display: 'more' }
         ]
       },
       { label: 'New here?', to: '/start', display: 'callout' }
     ]
   }
   ```

3. **Pick the layout.** The same options produce quite different panels:

   | You want | Set |
   | :-- | :-- |
   | Link columns beside a feature list | A first column with `hideLabel` and `display: 'feature'` entries, and `divided` on the second |
   | A grid of products | `columns: 3`, entries with `icon`, `description` and `display: 'feature'`, and a closing `display: 'callout'` |
   | A wide panel with an intro | `width: 'full'`, `columns: 6`, `divided`, and a first column with `span: 2`, `image` and `description` |
   | An image over every column | `width: 'full'`, and `image` on each column |

4. **Add your own cell, if the shapes run out.** `component` names a globally
   registered component, which replaces the entry's content, fills its cell and
   receives the entry as `link`. Name the file `.global.vue`, because `app.config`
   can only refer to it by name. An opaque component hides the highlight the menu
   paints behind an entry, so draw your own:

   ```vue [app/components/MenuPromo.global.vue]
   <script setup lang="ts">
   defineProps<{ link: DuxtLink }>();
   </script>

   <template>
     <span
       class="flex h-full p-3 in-data-highlighted:ring-2"
     >
       {{ link.label }}
     </span>
   </template>
   ```

5. **Use the second row the same way.** `sections` takes the same shape. A
   section with a menu belongs to the area of its first link, and when two entries
   claim a page the first one stays lit, so plain entries belong before menus that
   repeat their links.

6. **Check it on a phone.** Below the `lg` breakpoint the sheet shows the first
   level, and every menu slides in as a level of its own under a back button.
   Columns of a mega menu stay on one level, under their names.

::

## Why it works this way

A mega menu is centred on the page rather than on its entry. A panel this wide
has no sensible position relative to one entry in a row: hung from the entry,
the same menu sat somewhere else for every entry and every window width.

The sheet drills down rather than indenting, because each nested level takes
width from the one before it and a phone has none to spare. One level at a time
also keeps every link at full width, whatever the depth.

Every option is listed in the [configuration
reference](/reference/configuration), and the components are
[DuxtNavigationMenu](/reference/components/navigation/duxt-navigation-menu) and
[DuxtSheetDrill](/reference/components/navigation/duxt-sheet-drill).

## Checklist

- [ ] Every entry that opens a menu has `children`, and a `to` only where its own page should lead that menu
- [ ] A mega menu's `columns` add up with the cells' `span` values
- [ ] Plain entries in `sections` come before menus that repeat their links
- [ ] The menu has been opened at a phone width, down to its deepest level
