El primer panel que abrir, porque todo lo demás de la pestaña está aguas abajo de
él. Una fila por cada **fuente resuelta**: lo que quien la consume escribió como
un puñado de entradas, expandido en las colecciones que Content generó realmente
y el prefijo de URL bajo el que sirve cada una.

::devtools-panel{tab="sources"}
::

## Columnas

| Columna             | Qué dice                                                             |
| :------------------ | :------------------------------------------------------------------- |
| `Prefix`            | El segmento de URL bajo el que se sirve esta colección; `/` para la que no tiene prefijo |
| `Collection`        | El nombre de colección generado, tal como lo toma `queryCollection`, etiquetado con su tipo cuando es una sección generada |
| `Repository`        | De dónde vienen las páginas, enlazado cuando se conoce               |
| `Folder / artefact` | La `path` dentro de ese repositorio — una carpeta de documentación, o el artefacto a partir del que se construyó una sección |
| `Ref`               | La rama o etiqueta, y cuál de las dos es                             |
| `Version`           | El slug de la URL, `default` cuando se sirve sin segmento            |
| `Status`            | `current`, `deprecated` o `eol`, directamente desde la fuente        |
| `Reserved segments` | Nombres de carpeta dentro de esta fuente que un prefijo ya ha reclamado |

## Notas

**Un segmento de repositorio solo aparece cuando hay más de un repositorio**, y un
segmento de versión solo cuando hay más de una ref — un segmento que puede
contener un único valor no distingue nada. `sourceOptions.showRepo` y
`showVersion` los vuelven a forzar.

**Los segmentos reservados son la trampa por la que existe esta columna.** Si una
fuente se sirve bajo `/sdk` y su carpeta de documentación contiene un directorio
`v1-9/`, gana el prefijo y esa carpeta queda inalcanzable. El panel
[Comprobaciones](/reference/devtools/checks) lo informa como error; esta columna
muestra qué nombres están cogidos antes de que ocurra.

**Una sección generada es una colección como cualquier otra**, que es lo que
permite que el resto de la capa funcione sobre ella sin cambios — y lo que la
hacía indistinguible aquí de un árbol de documentación cuya carpeta se llamara
`CHANGELOG.md`. La etiqueta junto al nombre de la colección es su tipo, así que
las filas `changelog` y `openapi` se leen como lo que son, y el resumen las
cuenta. Lo que el propio artefacto tenía que decir es un hallazgo y no una
columna, y se informa en el panel
[Comprobaciones](/reference/devtools/checks).

El pie nombra el archivo del que se leyó la lista — útil en un sitio donde
`app.config.ts` no está donde esperabas.
