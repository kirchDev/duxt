La documentación la leen tanto los modelos como las personas, y las cuatro
respuestas de abajo se generan a partir de las mismas colecciones desde las que
se representan las páginas — así que ninguna puede desviarse de lo publicado.

| Ruta             | Qué es                                                                    |
| :--------------- | :------------------------------------------------------------------------ |
| `/llms.txt`      | Un índice: nombre del sitio, resumen y cada página como entrada enlazada    |
| `/llms-full.txt` | Las mismas páginas, enteras, concatenadas en un único archivo Markdown      |
| `<página>.md`    | El código Markdown de cualquier página                                     |
| `/mcp`           | Un servidor MCP — `list_pages`, `search_docs`, `read_page`                  |

## Markdown, no HTML

Todo lo de aquí entrega el Markdown tal como se escribió, y por eso el esquema
de la colección pide a Content que almacene `rawbody`. Un modelo al que se le da
HTML representado tiene que deshacer un diseño para encontrar un encabezado; uno
al que se le da la fuente lee lo que escribió el autor, con los bloques de
código todavía como bloques y un bloque MDC todavía como una llamada a
componente.

`<página>.md` lo sirve un **middleware** en lugar de una ruta, porque `.md` es
un sufijo del último segmento de la ruta y no un segmento propio — no existe un
patrón de ruta de Nitro que signifique «cualquier ruta que termine en .md».

## Por qué los dos archivos llms

La convención de [llmstxt.org](https://llmstxt.org) nombra dos, y responden a
preguntas distintas: un modelo que ha leído el índice todavía tiene que
descargar sesenta páginas, y uno al que se le entrega el archivo completo ya las
ha leído. Cuál sale más barato depende de la pregunta, así que el sitio publica
ambos.

## Por qué un servidor MCP real

`/mcp` habla el protocolo mediante el SDK oficial en lugar de ser un endpoint
JSON de diseño propio de duxt. Un cliente se conecta a él como se conecta a
cualquier otra cosa, en vez de que alguien escriba un adaptador alrededor de una
forma que solo tiene este tema.

Su búsqueda es un `LIKE` sobre títulos y descripciones, no el índice que usa el
navegador: ese se construye en el cliente a partir del volcado de la colección,
y una herramienta de servidor tiene la propia base de datos.
