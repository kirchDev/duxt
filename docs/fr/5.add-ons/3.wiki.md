`@kirchdev/duxt-wiki` rend une source sous forme de wiki plutôt que de
documentation : l’article occupe toute la largeur, la table des matières passe dans
le texte et les pages se lient entre elles par leur nom. Les pages restent du
Markdown dans Git. La couche n’ajoute ni éditeur dans le navigateur, ni comptes, ni
commentaires. Voyez-la à l’œuvre dans la [démo de wiki](https://duxt.app/demo/wiki).

## Ajouter la couche

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@kirchdev/duxt', '@kirchdev/duxt-wiki']
})
```

Attribuez ensuite le type de page `article` à une source :

```ts [app/app.config.ts]
export default defineAppConfig({
  duxt: {
    sources: [
      { path: 'wiki', slug: 'wiki', pageType: 'article' }
    ]
  }
})
```

::callout{type="warning"}
La couche ajoute des colonnes Content, des composants et des types de page : son
installation nécessite donc une seule fois une nouvelle image applicative. Ensuite,
les pages, les alias, les catégories et les nouveaux champs d’infobox sont des
modifications de contenu. Ils peuvent atteindre un serveur Node actif grâce aux
[bundles de contenu](/concepts/runtime-content-bundles).
::

## Types de page

Le `pageType` d’une source s’applique à toutes ses pages. Une page le remplace avec
`type` dans son frontmatter.

| Type             | Utilisé pour                                                  |
| :--------------- | :------------------------------------------------------------ |
| `article`        | Une page ordinaire, avec le plan après le paragraphe d’introduction |
| `category`       | Une page qui présente une catégorie et liste ses membres      |
| `disambiguation` | Une page qui renvoie un titre partagé vers ses différents sens |

La navigation de gauche est désactivée, car un wiki se lit à travers ses liens.
Réactivez-la pour tout le site avec `wiki: { sidebar: true }` dans `app.config.ts`.

## Lier par le nom

`[[Target]]` crée un lien vers une page par son titre, l’un de ses alias ou son
chemin. Le lien est résolu au rendu de la page : renommer une cible n’oblige donc pas
à réécrire les pages qui pointent vers elle.

```md
[[Crown Light]]
[[Crown Light|the outer beacon]]
[[Crown Light#History]]
[[guides/mooring]]
[[~/other-source/Harbour map]]
```

Les noms ne tiennent pas compte de la casse. Un lien cherche dans sa propre source et
sa version, puis dans les langues de repli de cette source. Un `~/` initial sort
explicitement de cette portée. Le code en ligne et les blocs délimités restent
littéraux.

Donnez d’autres noms à une page avec `aliases: [Outer Light]` dans son frontmatter.
Lorsqu’un nom correspond à plusieurs pages, une page `disambiguation` portant ce titre
l’emporte. Sans elle, le lien reste rouge et la compilation émet un avertissement,
car deviner enverrait les lecteurs sur la mauvaise page.

## Liens rouges et backlinks

Un lien vers une page inexistante est affiché en rouge et ne fait jamais échouer la
compilation. Il ouvre la page `/wanted?title=…` de la source, qui explique que la page
manque et liste celles qui pointent vers elle. Sur une forge reconnue, cette page
propose un formulaire prérempli pour créer le fichier, afin que l’écriture continue
de passer par Git. Ouvrir `/wanted` sans titre liste toutes les pages manquantes.

Chaque article se termine par les pages qui pointent vers lui. Les téléchargements en
Markdown brut, MCP et `llms-full.txt` reçoivent des liens ordinaires, et un nom non
résolu devient du texte brut : un lecteur automatique ne voit donc jamais `[[…]]`.

## Catégories et navbox

Listez les catégories d’une page dans son frontmatter :

```md
---
title: Crown Light
categories: [Beacons]
---
```

Les pages de catégorie se trouvent sous `<source>/category/<name>`, et les
`categories` propres à la page sont ses parents. Une catégorie qui a des membres
fonctionne sans page dédiée. Écrivez-en une avec `type: category` lorsqu’elle a
besoin d’une introduction.

Une navbox affiche une catégorie et ses sous-catégories sous forme de bloc de liens.
Elle n’apparaît que là où vous la placez :

```mdc
::navbox{category="Beacons"}
::
```

## Infobox et requêtes

Placez une infobox au début du corps de l’article, avant le chapeau. Elle flotte à
côté du texte sur un grand écran et s’empile au-dessus sur un téléphone.

```mdc
::infobox{title="Crown Light" image="/crown.svg" type="beacon"}
:::infobox-row{label="Status" key="status"}
Lit
:::
:::infobox-group{title="Visit" collapsed}
::::infobox-row{label="Base" key="base"}
[[Lumen Harbour]]
::::
:::
::
```

Les lignes peuvent contenir du Markdown et des wikiliens. La compilation enregistre
aussi le texte brut de chaque ligne comme donnée de page, sous sa `key` ou, à défaut,
sous son libellé. Définissez une `key` sur toute ligne dont le libellé est traduit,
afin que chaque langue enregistre le même champ.

`::query` liste les pages selon ces données, dans la source et la version actuelles :

```mdc
::query{type="beacon" where="status=Lit" columns="title,base"}
::
```

`where` compare un seul `key=value` sous forme de texte sensible à la casse : `01` et
`1` sont donc différents. `columns` vaut `title` par défaut, ce qui crée un lien vers
la page.

## Repérer ce qui demande de l’attention

[`duxt report`](/reference/cli) ajoute à sa sortie les pages demandées, orphelines,
en impasse et sans catégorie.

## Liste de contrôle

- [ ] `@kirchdev/duxt-wiki` vient après `@kirchdev/duxt` dans `extends`
- [ ] La source indique `pageType: 'article'`
- [ ] Une nouvelle image applicative a été construite après l’installation de la couche
- [ ] Les titres partagés par plusieurs pages ont une page `disambiguation`
- [ ] Les lignes aux libellés traduits portent une `key`
- [ ] `duxt report` n’affiche aucune page demandée que vous comptiez écrire
