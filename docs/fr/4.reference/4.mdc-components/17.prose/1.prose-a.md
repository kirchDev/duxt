Chaque lien d’une page Markdown passe par ce composant.

## Ce qu’il ajoute

Un chemin de documentation est réécrit pour porter le préfixe de la source d’où
vient la page, plus la locale du lecteur. Une URL externe est laissée telle
quelle et reçoit le nouvel onglet et la flèche.

## Pourquoi

Markdown n’a aucune idée qu’il est servi sous un préfixe. `/getting-started`
écrit dans le `docs/` de ce dépôt est correct sur un site à une seule source et
un 404 sur un site à deux, où la même page vit sur `/duxt/getting-started` — et
l’auteur du Markdown, qui peut être un tout autre dépôt, ne peut pas savoir
lequel des deux.

Pire, le même fichier est servi sous plusieurs préfixes à la fois dès qu’il est
publié en plus d’une version : un lien ne peut pas être réécrit à la
compilation, car il n’y a pas de réponse juste unique. Il est résolu à chaque
rendu, selon la source depuis laquelle la page est lue — ainsi un lien à
l’intérieur de `v0.7.0` garde le lecteur dans `v0.7.0`.

## API

### Props

| Prop     | Type      | Remarques                                |
| :------- | :-------- | :--------------------------------------- |
| `href`   | `string`  | Tel qu’écrit dans le Markdown            |
| `target` | `string`  | Défini pour un lien externe              |
