Chaque commande répond à `--help` avec ses options, même sur un site qui n’a jamais
été compilé. Cette sortie fait autorité : cette page indique donc seulement à quoi
sert chaque commande.

| Commande            | À quoi elle sert                                                          | Expliquée dans                                               |
| :------------------ | :------------------------------------------------------------------------ | :----------------------------------------------------------- |
| `duxt report`       | Affiche les sources, les vérifications et les redirections en Markdown, ou sous forme de données avec `--json` | [Ce que la compilation vérifie](/concepts/build-checks) |
| `duxt content pack` | Construit un bundle de contenu immuable sans compiler l’application       | [Créer des bundles de contenu](/guides/pack-content-bundles) |
| `duxt-cache-key`    | Affiche la clé de cache et les chemins des sources Content distantes      | [Mettre en cache les sources distantes et images OG](/guides/cache-build-work) |
| `duxt-og-cache`     | Affiche la clé de cache des images rendues, ou indique ce qu’une compilation a réutilisé | [Mettre en cache les sources distantes et images OG](/guides/cache-build-work) |

Lancez-les avec votre gestionnaire de paquets, par exemple `pnpm exec duxt report`.
`duxt report` a besoin d’un site préparé ou compilé, car il lit les métadonnées de
couche enregistrées par cette étape.
