`redirectFrom` dans le frontmatter d’une page devient des route rules, une par
préfixe sous lequel la page est servie. Ce panneau relit ces règles **depuis le
serveur en marche** au lieu de les recalculer : une règle générée et une règle
livrée sont deux affirmations différentes, et seule la seconde redirige quelqu’un.

::devtools-panel{tab="redirects"}
::

## Written by

Relire les règles, c’est lire celles de tous les modules, pas seulement celles de
la couche — `@nuxtjs/sitemap` ajoute `/sitemap.xml` sur tout site à plus d’un
sitemap. Chaque ligne dit donc qui l’a écrite :

| Badge            | Signification                                                |
| :--------------- | :------------------------------------------------------------- |
| `redirectFrom`   | Générée par duxt depuis le frontmatter d’une page               |
| `another module` | La route rule de quelqu’un d’autre, servie par le même serveur  |

Rien dans une route rule ne consigne son auteur : la couche note donc à côté les
chemins qu’elle a générés, et le panneau marque le reste.

## Notes

**Une règle par préfixe.** Une ancienne URL était enregistrée sous exactement l’un
des segments de dépôt, de version et de langue — et rien ne dit lequel —, donc
chaque combinaison redirige.

Une page qui redirige vers elle-même est écartée plutôt que livrée : c’est une
boucle, pas une redirection.
