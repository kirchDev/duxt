Le débogueur de chemins, et le panneau où se trouvent la plupart des bugs de
version. Tous ceux qu’a connus cette couche étaient un désaccord entre l’allure
d’une URL et la source qui la revendique — `/workflows/v0.7.0` en 404,
`/workflows/v0.7.0/v0.7.0` généré. Les deux étaient de l’arithmétique de préfixes
que rien n’affichait.

::devtools-panel{tab="paths"}
::

## Les étapes

1. **Le segment de langue est retiré.** `/de/sdk/guides/caching` est la page
   `/sdk/guides/caching` en allemand — la langue traduit l’interface, jamais
   l’arbre de contenu, et toute requête du thème vise donc le chemin raccourci.
2. **Le plus long préfixe correspondant gagne.** Une page sous `/sdk/v1-9`
   correspond aussi à `/sdk` ; prendre le plus court, c’est ainsi qu’un tag finit
   par rendre `main`.
3. **La collection qui la revendique est interrogée** sur ce chemin exact.
4. **La même page est cherchée dans les sources sœurs** — les autres versions et
   langues du même dépôt, jamais d’un autre.

## Lire un échec

Une page absente ici et présente dans une autre colonne, c’est le cas du
**fallback** : le sélecteur de versions la propose, et le lecteur est envoyé vers
l’ancêtre le plus proche plutôt que vers un 404.

Une page absente partout est une faute de frappe, et le panneau liste alors les
chemins les plus proches de la collection — ceux qui partagent la plus longue
amorce avec ce que vous avez collé.

::callout{type="tip"}
Collez l’URL exactement telle que le navigateur l’affiche, segment de langue
compris. Le raccourcissement, c’est l’affaire du panneau, et le voir faire est la
moitié de la réponse.
::
