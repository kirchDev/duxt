Le premier panneau qu’on ouvre, car tout le reste de l’onglet en découle. Une ligne
par **source résolue** : ce qu’un consommateur a écrit en une poignée d’entrées,
déplié en collections que Content a réellement générées, et le préfixe d’URL que
chacune sert.

::devtools-panel{tab="sources"}
::

## Colonnes

| Colonne             | Ce qu’elle dit                                                  |
| :------------------ | :---------------------------------------------------------------- |
| `Prefix`            | Le segment d’URL de cette collection ; `/` pour celle sans préfixe |
| `Collection`        | Le nom de collection généré, tel que `queryCollection` le prend    |
| `Repository`        | D’où viennent les pages, en lien dès qu’il est connu               |
| `Folder`            | Le `path` dans ce dépôt                                            |
| `Ref`               | La branche ou le tag — et lequel des deux                          |
| `Version`           | Le slug dans l’URL, `default` pour celle servie sans segment       |
| `Status`            | `current`, `deprecated` ou `eol`, directement depuis la source     |
| `Reserved segments` | Noms de dossier de cette source qu’un préfixe a déjà réservés      |

## Notes

**Un segment de dépôt n’apparaît qu’à partir du deuxième dépôt**, un segment de
version qu’à partir de la deuxième ref — un segment qui ne peut prendre qu’une
valeur ne distingue rien. `sourceOptions.showRepo` et `showVersion` les imposent
malgré tout.

**Les segments réservés sont le piège pour lequel cette colonne existe.** Si une
source est servie sous `/sdk` et que son dossier de documentation contient un
répertoire `v1-9/`, le préfixe gagne et ce dossier est injoignable. Le panneau
[Checks](/reference/devtools/checks) le signale comme une erreur ; cette colonne
montre quels noms sont pris avant que cela arrive.

Le pied de page nomme le fichier d’où la liste a été lue — utile sur un site dont
l’`app.config.ts` n’est pas là où vous l’attendiez.
