Sept langues et un fichier JSON par espace de noms font de la dérive une question
de temps — et vue-i18n répond à une clé manquante en imprimant la clé : un trou
apparaît donc comme un bouton libellé `duxt.nav.open` sur une page que personne n’a
ouverte dans cette langue.

::devtools-panel{tab="i18n"}
::

## Colonnes

| Colonne           | Ce qu’elle dit                                                   |
| :---------------- | :------------------------------------------------------------------ |
| `Directory`       | Un dossier sous `i18n/locales` ; `base` marque celui de référence    |
| `Keys`            | Combien de clés il définit en tout                                   |
| `Missing vs base` | Les clés que la base a et que celui-ci n’a pas                       |
| `Not in base`     | Les clés qu’il a et que la base n’a pas — souvent un renommage       |

## Notes

**Manquer est un fait, pas un verdict.** Un fichier de langue peut délibérément ne
contenir que ses écarts : `pt-BR` remplace une poignée de chaînes et lit le reste
depuis `pt` par le repli sur la langue de base — une longue liste sous « missing »
y est donc le principe qui fonctionne.

**« Not in base » se lit deux fois.** Une clé que personne d’autre n’a est le plus
souvent une faute de frappe ou un renommage resté à mi-chemin — et elle s’imprimera
elle-même sur la page.

La ligne au-dessus du tableau liste les langues que le site sert vraiment, ce qui
est une autre liste que les dossiers sur le disque : plusieurs langues peuvent en
partager un.
