Chaque clé que lit le thème, avec un badge disant d’où elle vient. « Pourquoi
l’entrée de duxt est-elle encore dans ma barre de navigation ? » coûte ici un
regard au lieu d’une séance.

::devtools-panel{tab="config"}
::

## Les badges

| Badge      | Signification                                                    |
| :--------- | :----------------------------------------------------------------- |
| `consumer` | Votre `app.config.ts` l’a définie                                  |
| `layer`    | C’est la valeur par défaut de la couche, intacte                   |
| `build`    | Elle a été calculée par le build et n’est écrite nulle part        |

## La règle de fusion

**Les tableaux sont remplacés en entier, les objets fusionnent clé par clé.** La
`navigation` d’un consommateur est la navigation — les entrées de la couche ont
disparu. Son `footer.note` laisse `footer.columns` tranquille.

Ce n’est pas ce que fait Nuxt avec `app.config` tout seul : defu concatène les
tableaux, un site aurait donc ses entrées plus les nôtres, sans moyen de retirer
les nôtres. La couche ne publie donc aucune liste dans `app.config` et les fusionne
elle-même.

## Notes

**Les valeurs structurées se déplient.** Une ligne contenant un objet ou une liste
affiche un décompte et un aperçu d’une ligne ; un clic imprime la valeur entière,
indentée. Elle reste dans la page une fois repliée : le filtre trouve donc toujours
une ligne par n’importe quelle chaîne qu’elle contient — y compris une seule
traduction d’un libellé.

`resolvedSources` est la seule clé que personne n’écrit : c’est le manifeste que le
build a calculé à partir de `sources`, et que lit tout autre panneau de cet onglet.
