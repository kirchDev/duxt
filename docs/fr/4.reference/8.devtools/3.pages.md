Ce que Content a fini par produire, un bloc par collection. C’est le panneau qui
répond à « ma page est-elle seulement dans le build ? » — et, plus souvent, à
« pourquoi celle-ci ne ressemble-t-elle pas aux autres ? ».

::devtools-panel{tab="pages"}
::

## Colonnes

| Colonne        | Ce qu’elle dit                                                     |
| :------------- | :------------------------------------------------------------------ |
| `Path`         | L’URL, préfixe compris — ce que `queryCollection` stocke             |
| `Title`        | Du frontmatter ; `missing` est un avertissement, pas une supposition |
| `Description`  | S’il en existe une ; elle alimente les cartes, l’image OG et llms.txt |
| `Icon`         | Le nom Iconify du frontmatter                                        |
| `Last updated` | De l’historique git, pas de la date du fichier                       |
| `Contributors` | Combien de personnes l’historique nomme                              |
| `File`         | Ouvre le fichier source dans votre éditeur                           |

## Notes

**Une collection sans aucun historique** est en général une source distante sans
`history: true`. Content clone en `--depth 1` : le checkout ne contient qu’un
commit et chaque page semblerait écrite par la personne qui a coupé la pointe — la
couche préfère aucune donnée à une donnée fausse.

**À partir de la deuxième collection, tout est replié.** Un site à cinq versions a
cinq tableaux presque identiques, et les cinq dépliés, personne ne les lit.

**Le filtre apparaît au-dessus des tableaux de plus de douze lignes.** Il masque
les lignes qui ne correspondent nulle part, compte celles qui restent, et un
rechargement ramène tout.

**Une collection vide est un constat, pas un tableau vide** — toute URL sous ce
préfixe est un 404, et le panneau le dit là où les lignes auraient été.
