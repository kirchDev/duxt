Chaque source distante est clonée dans `.data/content` et y reste. Rien dans un
build ne mentionne ce répertoire, donc rien ne le suggère quand cela tourne mal.

::devtools-panel{tab="cache"}
::

## Pourquoi cela compte

Un répertoire périmé a coûté ici du temps bien réel : un tag a été récupéré comme
une branche, la récupération a échoué, et le dossier à moitié écrit a continué de
répondre pour la configuration pourtant corrigée jusqu’à ce que quelqu’un le
supprime à la main. Le build ne disait rien : pour lui, la source était déjà
téléchargée.

**Drop** supprime une entrée ; le build suivant la retélécharge.

## Notes

Content indexe un répertoire par dépôt **et** par ref : une entrée pour une ref que
vous avez renommée n’est donc jamais réutilisée — ni jamais nettoyée. C’est dans ce
panneau qu’on les trouve.

::callout{type="warning"}
Jeter une entrée supprime un répertoire sur votre disque. Ce n’est jamais que le
cache — jamais une source de vérité —, mais c’est une vraie suppression, et c’est
pourquoi cet onglet n’est pas enregistré dans un build.
::
