---
title: Déplacer une page
description: redirectFrom dans le frontmatter, transformé en règles de route sous chaque préfixe.
icon: lucide:signpost
---

Une page déplacée est le seul lien cassé qu’un site de documentation se crée
lui-même. Mettez l’ancienne URL dans le frontmatter de la nouvelle page, et la
redirection part dans le même commit que le déplacement.

## Étapes

::steps
1. **Déplacez le fichier** et renommez-le comme vous l’entendiez.

2. **Listez les anciens chemins sur la page elle-même**, sans aucun préfixe :

   ```md [docs/3.guides/6.deploy-a-site.md]
   ---
   title: Déployer un site
   description: Où un site duxt peut tourner.
   redirectFrom:
     - /getting-started/deploy
     - /deployment
   ---
   ```

3. **Recompilez.** La compilation transforme chaque entrée en règles de route —
   sous chaque préfixe de dépôt, de version et de locale où la page est servie.

4. **Vérifiez-en une**, préfixe compris, sur le site compilé.

::

## Pourquoi le frontmatter est le bon endroit

Le correctif a toujours vécu hors du site : une règle nginx, un fichier
`_redirects` Netlify, une liste Cloudflare — écrits par celui qui déploie le
site et jamais par celui qui a déplacé la page. Et seule la couche peut le
résoudre une fois pour toutes, car seul le manifeste résolu sait quels préfixes
existent ; celui qui écrirait les règles à la main devrait redécouvrir tout le
schéma page par page.

::callout{type="tip" title="Réordonner ne nécessite jamais de redirection"}
Le préfixe numérique est retiré de l’URL : renommer `3.guides/` en `4.guides/`
ne déplace rien. Seule la partie après le point constitue l’URL.
::

## Liste de contrôle

- [ ] Chaque ancien chemin est listé, écrit sans préfixe
- [ ] La compilation ne signale aucun lien interne cassé
- [ ] Une ancienne URL redirige aussi sous le préfixe de version, pas seulement
      nue
- [ ] Rien n’a été ajouté à la configuration du serveur web
