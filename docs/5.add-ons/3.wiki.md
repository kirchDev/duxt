`@kirchdev/duxt-wiki` renders a source as a wiki rather than as documentation:
the article takes the full width, the table of contents moves into the text, and
pages link to each other by name. Pages stay Markdown in Git. The layer adds no
browser editor, accounts or comments. See it working in the
[wiki demo](https://duxt.app/demo/wiki).

## Add the layer

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@kirchdev/duxt', '@kirchdev/duxt-wiki']
})
```

Then give a source the `article` page type:

```ts [app/app.config.ts]
export default defineAppConfig({
  duxt: {
    sources: [
      { path: 'wiki', slug: 'wiki', pageType: 'article' }
    ]
  }
})
```

::callout{type="warning"}
The layer adds Content columns, components and page types, so installing it needs
a new application image once. After that, pages, aliases, categories and new
infobox fields are content changes. They can reach a running Node server through
[content bundles](/concepts/runtime-content-bundles).
::

## Page types

A source's `pageType` applies to every page in it. A page overrides it with
`type` in its frontmatter.

| Type             | Used for                                                      |
| :--------------- | :------------------------------------------------------------ |
| `article`        | An ordinary page, with the outline after the lead paragraph   |
| `category`       | A page that introduces a category and lists its members       |
| `disambiguation` | A page that sends one shared title to its several meanings    |

The left navigation is off, because a wiki is read through its links. Turn it
back on for the whole site with `wiki: { sidebar: true }` in `app.config.ts`.

## Link by name

`[[Target]]` links to a page by its title, one of its aliases or its path. The
link resolves when the page is rendered, so renaming a target needs no rewrite of
the pages that point at it.

```md
[[Crown Light]]
[[Crown Light|the outer beacon]]
[[Crown Light#History]]
[[guides/mooring]]
[[~/other-source/Harbour map]]
```

Names ignore case. A link looks in its own source and version, then in that
source's locale fallbacks. A leading `~/` leaves that scope explicitly. Inline
code and fenced blocks stay literal.

Give a page more names with `aliases: [Outer Light]` in its frontmatter. When a
name fits several pages, a `disambiguation` page with that title wins. Without
one, the link stays red and the build warns, because guessing would link readers
to the wrong page.

## Red links and backlinks

A link to a page that does not exist is drawn in red and never fails a build. It
opens the source's `/wanted?title=…` page, which explains that the page is
missing and lists who links to it. On a recognised forge, that page offers a
prefilled proposal to create the file, so writing still happens through Git.
Opening `/wanted` without a title lists every missing page.

Each article ends with the pages that link to it. Plain Markdown downloads, MCP
and `llms-full.txt` receive ordinary links, and an unresolved name becomes plain
text, so a machine reader never sees `[[…]]`.

## Categories and navboxes

List a page's categories in its frontmatter:

```md
---
title: Crown Light
categories: [Beacons]
---
```

Category pages live at `<source>/category/<name>`, and the page's own
`categories` are its parents. A category with members works without any page of
its own. Write one with `type: category` when it needs an introduction.

A navbox draws one category and its subcategories as a block of links. It appears
only where you place it:

```mdc
::navbox{category="Beacons"}
::
```

## Infoboxes and queries

Put an infobox at the start of the article body, before the lead. It floats beside
the text on a wide screen and stacks above it on a phone.

```mdc
::infobox{title="Crown Light" image="/crown.svg" type="beacon"}
:::infobox-row{label="Status" key="status"}
Lit
:::
:::infobox-group{title="Visit" collapsed}
::::infobox-row{label="Base" key="base"}
[[Lumen Harbour]]
::::
:::
::
```

Rows may hold Markdown and wikilinks. The build also stores each row's plain text
as page data, under its `key` or, without one, its label. Set a `key` on any row
whose label is translated, so that every language stores the same field.

`::query` lists pages by that data, in the current source and version:

```mdc
::query{type="beacon" where="status=Lit" columns="title,base"}
::
```

`where` compares one `key=value` as case-sensitive text, so `01` and `1` differ.
`columns` defaults to `title`, which links to the page.

## Find what needs attention

[`duxt report`](/reference/cli) adds wanted, orphaned, dead-end and uncategorized
pages to its output.

## Checklist

- [ ] `@kirchdev/duxt-wiki` comes after `@kirchdev/duxt` in `extends`
- [ ] The source names `pageType: 'article'`
- [ ] A new application image was built after installing the layer
- [ ] Titles shared by several pages have a `disambiguation` page
- [ ] Rows with translated labels carry a `key`
- [ ] `duxt report` shows no wanted page you meant to write
