A duxt site is a Nuxt application. Anything that runs Nuxt runs it.

## Static

`nuxt generate` produces a folder of HTML. This is the right default for
documentation: no server, no runtime cost, and every page is cached at the
edge.

::package-managers{command="run generate"}
::

::callout{type="warning" title="Remote sources are read at build time"}
A site reading another repository's `docs/` picks up changes when it builds,
not when they are pushed. Rebuild on a schedule, or trigger it from the source
repository.
::

## Server

`nuxt build` produces a Node server, which you need if pages must react to a
request — a private repository behind an auth check, for instance.

## What the build needs

- **Node 24.** The layer uses `node:sqlite` rather than a native driver.
- **Network access to your sources**, if any of them are remote repositories.
- **A token**, for private ones. Content reads it from the collection's `auth`.

## What the site serves besides pages

| Path             | What it is                                                        |
| :--------------- | :---------------------------------------------------------------- |
| `/llms.txt`      | The documentation as a Markdown index, per llmstxt.org             |
| `/llms-full.txt` | The same pages, whole, in one Markdown file                        |
| `/mcp`           | An MCP server over the same content — `list_pages`, `search_docs`, `read_page` |
| `/sitemap.xml`   | Every page of the current version, per locale                      |
| `/robots.txt`    | Generated by @nuxtjs/robots                                        |
| `/rss.xml`       | The feed, once `duxt.feed.path` names a section                    |
| `<page>.md`      | Any page's own Markdown source                                     |

All of them are generated from the collection the pages render from, so none can
drift from what is published.

## Environment

| Variable                     | When you need it                                    |
| :--------------------------- | :--------------------------------------------------- |
| `NUXT_PUBLIC_I18N_BASE_URL`  | Always, unless `i18n.baseUrl` is set in the config    |
| `NUXT_OG_IMAGE_SECRET`       | Rolling or multi-instance deploys                     |

`NUXT_PUBLIC_I18N_BASE_URL` is the origin the site is served from. It is what
`hreflang`, `canonical`, the sitemap and the Open Graph images are built
against, and duxt cannot guess it — see the SEO guide.

`NUXT_OG_IMAGE_SECRET` signs the Open Graph image URLs. Without it a secret is
generated per build, which is fine for one instance and wrong for two: a card
whose URL was signed by one instance is rejected by the next, so a link shared
during a rolling deploy loses its image. Generate one with
`npx nuxt-og-image generate-secret` and set it once — it does not rotate.

::callout{type="warning" title="Content is built in, not read at runtime"}
Content downloads a remote repository at build time and compiles it into the
database the build ships. A source that has moved on since is not picked up by a
running server — rebuild on a schedule, or trigger one from the source
repository. There is no supported path for refreshing that database in place.
::
