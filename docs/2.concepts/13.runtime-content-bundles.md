Content bundles are an opt-in deployment path for a Node server with file-backed
SQLite and server-rendered documentation. They let an operator publish Markdown
and documentation media without rebuilding the app. Leave the bundle directory
unset to keep the ordinary deployment behavior. Workers, static output, Bun,
Deno and other database adapters do not use this importer.

[ADR-0013](/adr/0013-load-content-bundles-at-runtime) records why this narrows the
rebuild default rather than replacing it. Follow [Pack content bundles](/guides/pack-content-bundles)
for the app/packer image, compatibility artefact and runtime setup.

## Content changes and code changes

An image fixes the collections, schemas, resolved sources, versions and component
code. A bundle may change pages, frontmatter, redirects and documentation media
within that structure. Adding a source or version, changing a schema, adding an
MDC component, or changing the theme still requires a new app image and matching
packer. Generated sections may change their pages without changing their declared
configuration.

`compatHash` covers structural compatibility. `usedComponents` is checked
separately as a subset of the image's `availableComponents`. In bundle mode,
components under `app/components/content/` from the consumer and every extended
layer are registered as lazy globals, including components no build-time page
used. Existing global Content/MDC components remain available. An unused UI or
layout component outside those content directories is not promised by the
scanned component list. Put content components in the content directory before
building the image; a bundle carries data, never new Vue code.

## One activation per request

The server validates hashes, structure, component availability and all dumps
before importing every collection in one SQLite transaction. New HTTP requests
wait for activation; admitted renders and their background work finish first.
After commit, matching Content checksums, redirects and media belong to the new
activation. Readers do not observe half-imported collections.

At startup a missing or rejected bundle falls back to the image. After a
successful activation, rejection keeps the active bundle. Rejected identifiers
are not retried: repair the content and publish a new immutable bundle. Restarts
with matching stored checksums skip replay. Protect both directories and the
database as application data; file hashes are integrity checks, not signatures.

## Browsers and replicas have boundaries

A full page load carries the admitted server's checksums in its SSR payload.
The client applies them before its first Content query, so an old `localStorage`
dump no longer matches and Content fetches the active dump with its new `?v=`.
An already-open tab may keep the old content through SPA navigation until its
next full load. There is no live browser synchronization.

Each replica polls independently. A publication can take `pollSeconds` (default
30), plus validation/import time and draining existing renders, to reach every
replica. The layer provides no coordinated switch or sticky sessions. Keep
complete bundle directories available to every replica before publishing
`current`. A prerendered HTML page is still a build artefact; disable prerendering
for documentation you want to update at runtime.

## Derived state and operator ownership

Activation replaces redirects and documentation media, and clears MCP path,
OG-image runtime and sitemap caches. OG images render again on demand; that
short burst is accepted. Native IPX still serves transformed images: the operator
must configure its filesystem roots before process start, as the guide shows.

`duxt:search:records` remains a build-time hook. An external search provider must
own refreshing its index; runtime bundles do not rebuild it. Transport is also
the operator's: a sidecar or sync job publishes immutable directories and writes
`current` last. duxt carries no S3 client, credentials, egress requirement or
replica coordinator. Structured logs and the optional protected status route
provide diagnostics; the layer publishes no metrics format.
