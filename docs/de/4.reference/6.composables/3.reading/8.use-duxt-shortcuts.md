## Signatur

```ts
const { shortcuts, keys, hint, on } = useDuxtShortcuts();

on('help', () => open());
```

```ts
const { open, toggle } = useDuxtShortcutSheet();
```

## Anmerkungen

Die eine Stelle, die weiß, welche Tasten belegt sind, damit das Overlay auf `?`
und die Handler sich nicht widersprechen können. `shortcuts` ist die Liste, die
die Richtlinie `shortcuts.singleCharacter` der Seite übrig lässt, `keys()`
zeichnet eine Belegung für die Tastatur des Lesers (`⌘` oder `Ctrl`), und `on()`
belegt eine Aktion mit allen Absicherungen, die eine globale Belegung braucht —
nie während der Leser tippt, nie in einem Dialog oder Menü, nie wenn etwas
Näheres die Taste schon behandelt hat und, bei den unbelegten Tasten, nur
solange der Seiteninhalt selbst den Fokus hält.

`hint()` ist `keys()` für ein Bedienelement statt für das Overlay: Es nimmt eine
Aktion, gibt die Tasten als eine Zeichenkette zurück — `⌘K`, `Ctrl+K`, `]` — und
gibt `undefined` zurück, wo die Richtlinie diese Aktion gelöst hat, sodass ein
Template `v-if` schreibt und keine leere Tastenkappe zeichnet. Genau das drucken
der Suchbutton und die Links auf die Nachbarseiten.

`useDuxtShortcutSheet()` ist der Öffnungszustand des Overlays — geteilt statt vom
Overlay besessen, weil `?` nicht der einzige Weg hinein ist: Der Trigger im
Kopfbereich öffnet denselben Dialog, und auf einer Seite mit
`shortcuts.singleCharacter: false` ist er das Einzige, was das kann. Siehe
[Tastenkürzel](/concepts/keyboard-shortcuts).
