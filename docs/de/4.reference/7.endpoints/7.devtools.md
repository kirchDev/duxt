::callout{type="danger" title="Im Build nie registriert"}
Das Panel zeigt die aufgelöste Konfiguration, die Dateipfade dahinter und eine
Schaltfläche, die ein Cache-Verzeichnis löscht. Nichts davon geht in der Produktion
irgendwen etwas an, und deshalb kehrt das Modul zurück, bevor es ausserhalb eines
Dev-Servers überhaupt etwas registriert.
::

## Antwort

`text/html`, ein Dokument je Panel: `/_duxt/devtools` ist das Sources-Panel, und
jedes weitere hängt darunter — `/_duxt/devtools/paths`, `/_duxt/devtools/pages` und
so fort, in der Reihenfolge der Tab-Zeile.

Dieselben Dokumente rahmen die Nuxt Devtools in ihrem **duxt**-Tab ein. Die Route
existiert also, damit man sie in einem eigenen Fenster öffnen kann — eine breite
Tabelle liest sich ausserhalb einer Schublade leichter.

## Hinweise

Was jedes Panel beantwortet, mit jedem Panel so dargestellt, wie es aussieht, ist
ein eigener Abschnitt: [Devtools](/reference/devtools).
