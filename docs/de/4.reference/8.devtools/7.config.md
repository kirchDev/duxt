Jeder Schlüssel, den das Theme liest, mit einem Badge, das sagt, woher er kam.
„Warum steht duxts Eintrag immer noch in meiner Navbar“ kostet hier einen Blick
statt einer Sitzung.

::devtools-panel{tab="config"}
::

## Die Badges

| Badge      | Bedeutung                                                        |
| :--------- | :--------------------------------------------------------------- |
| `consumer` | Deine `app.config.ts` hat ihn gesetzt                            |
| `layer`    | Es ist der Standard der Ebene, unangetastet                      |
| `build`    | Er wurde vom Build berechnet und steht nirgends geschrieben      |

## Die Merge-Regel

**Arrays werden ganz ersetzt, Objekte werden Schlüssel für Schlüssel
zusammengeführt.** Die `navigation` eines Konsumenten ist die Navigation — die
Einträge der Ebene sind weg. Die `footer.note` eines Konsumenten lässt
`footer.columns` in Ruhe.

Das ist nicht, was Nuxt von sich aus mit `app.config` macht: defu hängt Arrays
aneinander, was einer Seite ihre eigenen Einträge plus die der Ebene gäbe, ohne
eine Möglichkeit, unsere zu entfernen. Deshalb liefert die Ebene überhaupt keine
Listen in `app.config` aus und führt sie selbst zusammen.

## Hinweise

**Strukturierte Werte lassen sich öffnen.** Eine Zeile, die ein Objekt oder eine
Liste hält, zeigt eine Anzahl und eine einzeilige Vorschau; ein Klick darauf
druckt den ganzen Wert eingerückt. Er bleibt auch zugeklappt in der Seite, der
Filter findet eine Zeile also weiterhin über jede Zeichenkette darin — auch über
eine einzelne Übersetzung eines Labels.

`resolvedSources` ist der eine Schlüssel, den niemand schreibt: es ist das
Manifest, das der Build aus `sources` berechnet hat, und jedes andere Panel in
diesem Tab liest es.
