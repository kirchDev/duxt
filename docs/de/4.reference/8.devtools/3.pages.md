Womit Content am Ende dasteht, ein Block je Collection. Das ist das Panel, das
„ist meine Seite überhaupt im Build“ beantwortet — und häufiger noch „warum
sieht diese hier anders aus als die übrigen“.

::devtools-panel{tab="pages"}
::

## Spalten

| Spalte         | Was sie sagt                                                       |
| :------------- | :----------------------------------------------------------------- |
| `Path`         | Die URL samt Präfix — das, was `queryCollection` speichert          |
| `Title`        | Aus dem Frontmatter; `missing` ist eine Warnung, keine Vermutung    |
| `Description`  | Ob überhaupt eine existiert; sie speist die Karten, das OG-Bild und llms.txt |
| `Icon`         | Der Iconify-Name im Frontmatter                                     |
| `Last updated` | Aus der Git-Historie, nicht aus der mtime der Datei                 |
| `Contributors` | Wie viele Personen die Historie nennt                               |
| `File`         | Öffnet die Quelldatei in deinem Editor                              |

## Anmerkungen

**Eine Collection ganz ohne Historie** ist meist eine entfernte Quelle ohne
`history: true`. Content klont mit `--depth 1`, also enthält der Checkout einen
einzigen Commit und jede Seite sähe so aus, als hätte sie geschrieben, wer die
Spitze geschnitten hat — die Ebene zieht keine Daten falschen Daten vor.

**Collections jenseits der ersten sind eingeklappt.** Eine Seite mit fünf
Versionen hat fünf nahezu identische Tabellen, und alle fünf ausgeklappt ist
eine Seite, die niemand liest.

**Der Filter erscheint über einer Tabelle mit mehr als zwölf Zeilen.** Er
blendet Zeilen aus, die nirgendwo in der Zeile passen, zählt, was übrig bleibt,
und ein Neuladen bringt alles zurück.

**Eine leere Collection ist ein Befund, keine leere Tabelle** — jede URL unter
diesem Präfix ist ein 404, und das Panel sagt das dort, wo die Zeilen gewesen
wären.
