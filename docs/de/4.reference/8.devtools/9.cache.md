Jede entfernte Quelle wird nach `.data/content` geklont und dort behalten. Nichts
in einem Build erwähnt dieses Verzeichnis, also weist auch nichts darauf hin,
wenn es schiefgeht.

::devtools-panel{tab="cache"}
::

## Warum das zählt

Ein veraltetes Verzeichnis hier hat einmal echte Zeit gekostet: Ein Tag wurde als
Branch geholt, das Holen schlug fehl, und der halb geschriebene Ordner
antwortete weiter für die reparierte Konfiguration, bis er von Hand gelöscht
wurde. Der Build sagte nichts, denn aus seiner Sicht war die Quelle bereits
heruntergeladen.

**Drop** entfernt einen Eintrag; der nächste Build lädt ihn erneut herunter.

## Hinweise

Content schlüsselt ein Verzeichnis nach Repository **und** Ref, ein Eintrag für
eine Ref, die du umbenannt hast, wird also nie wiederverwendet — und auch nie
aufgeräumt. In diesem Panel findest du sie.

::callout{type="warning"}
Einen Eintrag zu verwerfen löscht ein Verzeichnis auf deiner Platte. Es ist immer
nur der Cache — nie eine Quelle der Wahrheit — aber es ist eine echte Löschung,
und deshalb wird dieser Tab in einem Build nicht registriert.
::
