Sieben Locales und eine JSON-Datei pro Namespace machen Drift zur reinen
Zeitfrage — und vue-i18n beantwortet einen fehlenden Key damit, den Key
auszugeben, also zeigt sich eine Lücke als Button mit der Beschriftung
`duxt.nav.open` auf einer Seite, die in dieser Sprache niemand geöffnet hat.

::devtools-panel{tab="i18n"}
::

## Spalten

| Spalte            | Was sie sagt                                                     |
| :---------------- | :--------------------------------------------------------------- |
| `Directory`       | Ein Ordner unter `i18n/locales`; `base` markiert den, gegen den verglichen wird |
| `Keys`            | Wie viele Keys er insgesamt definiert                             |
| `Missing vs base` | Keys, die die Basis hat und dieser nicht                          |
| `Not in base`     | Keys, die dieser hat und die Basis nicht — meist eine Umbenennung |

## Hinweise

**Fehlend ist eine Tatsache, kein Urteil.** Eine Locale-Datei darf absichtlich nur
ihre Abweichungen enthalten: `pt-BR` überschreibt eine Handvoll Strings und liest
den Rest über den Rückfall auf die Basissprache aus `pt`, eine lange
„missing“-Liste ist dort also das Design bei der Arbeit.

**„Not in base“ ist das, was du zweimal lesen solltest.** Ein Key, den sonst
nichts hat, ist meist ein Tippfehler oder eine Umbenennung, die auf halber
Strecke stehen geblieben ist — und er druckt sich selbst auf die Seite.

Die Zeile über der Tabelle listet die Locales, die die Seite tatsächlich
ausliefert, und das ist eine andere Liste als die Ordner auf der Platte —
mehrere Locales können sich einen Ordner teilen.
