Der Pfad-Debugger, und das Panel, in dem die meisten Versionsfehler gefunden
werden. Jeder, den diese Ebene hatte, war eine Uneinigkeit darüber, wie eine URL
aussieht und welche Quelle sie beansprucht — `/workflows/v0.7.0`, das einen 404
lieferte, `/workflows/v0.7.0/v0.7.0`, das erzeugt wurde. Beides war Rechnerei
mit Präfixen, die nichts ausgab.

::devtools-panel{tab="paths"}
::

## Die Schritte

1. **Das Locale-Segment wird abgeschnitten.** `/de/sdk/guides/caching` ist die
   Seite `/sdk/guides/caching` auf Deutsch — das Locale übersetzt die
   Oberfläche, niemals den Inhaltsbaum, deshalb meint jede Suche im Theme den
   abgeschnittenen Pfad.
2. **Das längste passende Präfix gewinnt.** `/sdk/v1-9` und `/sdk` passen beide
   auf eine Seite unterhalb des ersten; das kürzere zu nehmen ist der Weg,
   auf dem ein Tag am Ende `main` rendert.
3. **Die beanspruchende Collection wird abgefragt** — nach genau diesem Pfad.
4. **Dieselbe Seite wird in den Geschwisterquellen gesucht** — den anderen
   Versionen und Sprachen desselben Repositories, niemals eines anderen.

## Einen Fehlschlag lesen

Eine Seite, die hier fehlt und in einer anderen Spalte vorhanden ist, ist der
Fall für den **Rückfall**: Der Versionsumschalter bietet sie an, und der Leser
wird zum nächstgelegenen Vorfahren geschickt statt auf einen 404.

Eine Seite, die überall fehlt, ist ein Tippfehler, und das Panel listet dann die
nächstgelegenen Pfade in der Collection auf — die, die den längsten führenden
Abschnitt mit dem teilen, was du eingefügt hast.

::callout{type="tip"}
Füge die URL genau so ein, wie der Browser sie zeigt, samt Locale-Segment. Das
Panel schneidet ab, und das zu sehen ist die halbe Antwort.
::
