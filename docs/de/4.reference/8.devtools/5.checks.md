Dieselben Prüfungen, die `pnpm build` ausführt, aus demselben Code — es geht
nicht um eine zweite Meinung, sondern um einen Ort, an dem die Befunde stehen
bleiben. Eine Warnung, die während eines Builds gedruckt wird, ist
weggescrollt, bevor sie jemand liest.

::devtools-panel{tab="checks"}
::

## Was geprüft wird

**Fehler** sind Dinge, die eine URL unerreichbar machen:

- eine **Collection ohne Seiten**, deren ganzes Präfix ein 404 ist;
- ein **Ordner, der wie ein Repository- oder Versionssegment heißt**, den das
  Präfix vollständig verdeckt.

**Warnungen** sind Dinge, die eine Seite still verschlechtern:

- **kein `title` oder keine `description`** — das Inhaltsverzeichnis, die Karten,
  das OG-Bild und llms.txt lesen sie alle;
- ein **Link auf eine Seite, die nichts ausliefert**, genau so aufgelöst, wie
  `ProseA` sie beim Rendern auflöst: zuerst unter dem eigenen Präfix der Quelle,
  dann nackt;
- ein **Link auf einen Anker, den diese Seite nicht hat**.

## Hinweise

Befunde nennen ihre Datei in Anführungszeichen, und das Panel macht aus der
ersten einen Link, der deinen Editor dort öffnet.

Die Links werden **nur intern** geprüft. Eine externe URL zu prüfen ist nicht
Sache dieses Builds, und es würde das Netzwerk in den Build holen.
