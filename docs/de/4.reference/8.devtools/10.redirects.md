`redirectFrom` im Frontmatter einer Seite wird zu Route Rules, eine je Präfix,
unter dem die Seite ausgeliefert wird. Dieses Panel liest diese Regeln **aus dem
laufenden Server** zurück, statt sie neu zu berechnen: Eine Regel, die erzeugt
wurde, und eine Regel, die ausgeliefert wurde, sind zwei verschiedene
Behauptungen, und nur die zweite leitet irgendjemanden um.

::devtools-panel{tab="redirects"}
::

## Geschrieben von

Die Regeln zurückzulesen heißt, die jedes Moduls zu lesen, nicht nur die der
Ebene — `@nuxtjs/sitemap` fügt auf jeder Seite mit mehr als einer Sitemap
`/sitemap.xml` hinzu. Also sagt jede Zeile, wer sie geschrieben hat:

| Badge            | Bedeutung                                                  |
| :--------------- | :----------------------------------------------------------- |
| `redirectFrom`   | Von duxt aus dem Frontmatter einer Seite erzeugt              |
| `another module` | Die Route Rule von jemand anderem, vom selben Server ausgeliefert |

Nichts in einer Route Rule hält ihren Urheber fest, also merkt sich die Ebene die
Pfade, die sie erzeugt hat, daneben, und das Panel markiert den Rest.

## Hinweise

**Eine Regel pro Präfix.** Eine alte URL wurde unter genau einem von
Repository-Segment, Versionssegment und Locale-Segment als Lesezeichen gespeichert
— und nichts sagt, unter welchem — also leitet jede Kombination um.

Eine Seite, die auf sich selbst umleitet, wird übersprungen statt ausgeliefert:
Das ist eine Schleife, kein Redirect.

Eine Seite zu verschieben ist ein eigener Leitfaden:
[Eine Seite verschieben](/guides/move-a-page).
