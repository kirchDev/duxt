Jeder Link in einer Markdown-Seite geht durch diese Komponente.

## Was sie hinzufügt

Ein Doku-Pfad wird umgeschrieben, sodass er das Präfix der Quelle trägt, aus der
die Seite kam, plus die Locale des Lesers. Eine externe URL bleibt unberührt und
bekommt den neuen Tab und den Pfeil.

## Warum

Markdown hat keine Ahnung davon, unter einem Präfix ausgeliefert zu werden.
`/getting-started`, geschrieben im `docs/` dieses Repositories, ist auf einer
Seite mit einer Quelle richtig und auf einer Seite mit zweien ein 404, wo
dieselbe Seite unter `/duxt/getting-started` liegt — und der Autor des Markdowns,
der in einem ganz anderen Repository sitzen kann, weiß nicht, welche von beiden.

Schlimmer noch: Dieselbe Datei wird unter mehreren Präfixen gleichzeitig
ausgeliefert, sobald sie in mehr als einer Version veröffentlicht ist. Ein Link
lässt sich zur Build-Zeit nicht umschreiben, weil es keine einzelne richtige
Antwort gibt. Er wird stattdessen je Render aufgelöst, gegen die Quelle, aus der
die Seite gerade gelesen wird — ein Link innerhalb von `v0.7.0` hält den Leser
also in `v0.7.0`.

## API

### Props

| Prop     | Typ       | Anmerkungen                              |
| :------- | :-------- | :--------------------------------------- |
| `href`   | `string`  | Wie im Markdown geschrieben              |
| `target` | `string`  | Bei einem externen Link gesetzt          |
