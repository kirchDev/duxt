Jedes Bild in einer Markdown-Seite.

## Was sie hinzufügt

**Zwei Varianten.** Ein Screenshot eines dunklen Editors auf einer weißen Seite —
oder umgekehrt — ist das häufigste hässliche Ding in einer Dokumentation, und CSS
kann es nicht beheben, weil die Pixel falsch sind, nicht der Rahmen. Eine Seite
darf eine zweite Datei benennen:

```md
![Die Seitenleiste](/shots/sidebar.png){dark="/shots/sidebar-dark.png"}
```

**Klick zum Zoomen**, sofern das Bild nicht darum bittet, es zu lassen:

```md
![Ein Diagramm](/diagram.svg){zoom="false"}
```

## API

### Props

| Prop   | Typ       | Standard | Anmerkungen                                       |
| :----- | :-------- | :------- | :------------------------------------------------ |
| `src`  | `string`  | —        | Wie geschrieben                                    |
| `alt`  | `string`  | —        | Wie geschrieben                                    |
| `dark` | `string`  | —        | Eine zweite Datei, unter dem dunklen Theme ausgeliefert |
| `zoom` | `boolean` | `true`   | `false` lässt das Bild inert                       |

## Anmerkungen

Die dunkle Variante wird ausdrücklich benannt, statt per Konvention geraten.
`-dark` aus einem Dateinamen abzuleiten heißt, dass eine fehlende Datei zu einem
kaputten Bild wird — und der Autor erfährt es nie.
