## Dokumentation schreiben

Markdown liegt in `docs/` im Wurzelverzeichnis deines Repositories — aufgelöst
gegen das Repository, nicht gegen das Verzeichnis, in dem die Seite läuft, damit
eine Seite in einem Unterordner sie findet. Eine Datei wird zur Seite, ein
Ordner zur Sektion, und das Frontmatter trägt Titel, Beschreibung und Icon.

::file-tree{title="dein-projekt/"}
---
tree:
  - name: docs/
    children:
      - name: index.md
      - name: 1.getting-started/
        children:
          - name: index.md
          - name: 1.installation.md
      - name: 2.guides/
        children:
          - name: 1.deploying.md
  - name: nuxt.config.ts
---
::

```md [docs/1.getting-started/index.md]
---
title: Einführung
description: Was dieses Projekt ist.
icon: lucide:rocket
---

Deine erste Seite.
```

Ein numerisches Präfix ordnet den Baum und wird aus der URL entfernt:
`1.getting-started/` wird unter `/getting-started` ausgeliefert. Eine Sektion
umzusortieren verschiebt deshalb nie eine URL — nur den Teil nach dem Punkt
umzubenennen tut das.

::callout{type="tip" title="Kein H1 im Text"}
Der `title` der Seite wird als `<h1>` gerendert. Eine eigene Überschrift am
Anfang der Datei wäre die zweite auf der Seite.
::

## Was der Build braucht

- **Node 24.** Die Ebene liest ihre Datenbank über `node:sqlite`, ein nativer
  SQLite-Treiber wird also weder installiert noch gebraucht.
- **Netzzugang zu deinen Quellen**, falls eine davon ein anderes Repository ist,
  und ein Token für die privaten — Content liest ihn aus dem `auth` der
  Collection.

## Ergebnis

`nuxt dev` liefert die Seite aus. Alles, was das Theme zeichnet, sind Daten mit
einem Standardwert — der nächste Schritt ist deshalb die eine Datei, die ihn
überschreibt: [Konfiguration](/getting-started/configuration).
