As mesmas verificações que o `pnpm build` faz, a partir do mesmo código — não se
trata de uma segunda opinião, mas de um sítio onde os achados ficam. Um aviso
impresso durante uma compilação já desapareceu do ecrã quando alguém o lê.

::devtools-panel{tab="checks"}
::

## O que é verificado

Os **erros** são coisas que tornam um URL inalcançável:

- uma **coleção sem páginas**, cujo prefixo inteiro é um 404;
- uma **pasta com nome de segmento de repositório ou de versão**, que o prefixo
  tapa por completo.

Os **avisos** são coisas que degradam uma página em silêncio:

- **sem `title` ou sem `description`** — o índice, os cartões, a imagem OG e o
  llms.txt lêem ambos;
- uma **ligação para uma página que ninguém serve**, resolvida exactamente como o
  `ProseA` a resolve ao desenhar: primeiro sob o prefixo da fonte, depois nua;
- uma **ligação para uma âncora que essa página não tem**;
- o que uma **secção gerada** não conseguiu compreender — um artefacto que não
  estava lá nessa ref, um de que o tipo não leu nada, um `$ref` que não resolve
  num documento OpenAPI, um título de changelog que parece uma release mas não é
  analisado como tal.

::callout{type="tip" title="As secções comunicavam noutro sítio"}
Um artefacto é analisado enquanto a configuração é carregada, por isso o que um
tipo não conseguia ler era impresso muito antes de um servidor de
desenvolvimento ter acabado de arrancar — e já lá não estava quando alguém
olhava. Esses achados passam agora por este painel, que é a razão inteira da sua
existência. Vê
[O que a compilação verifica](/concepts/build-checks).
::

## Notas

Os achados nomeiam o seu ficheiro entre aspas, e o painel transforma o primeiro
numa ligação que abre o teu editor nesse ponto.

As ligações são verificadas **apenas internamente**. Um URL externo não é desta
compilação verificar, e fazê-lo poria a rede dentro dela.
