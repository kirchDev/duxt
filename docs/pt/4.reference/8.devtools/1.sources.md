O primeiro painel a abrir, porque tudo o resto no separador vem depois dele. Uma
linha por **fonte resolvida**: o que um consumidor escreveu como um punhado de
entradas, desdobrado nas coleções que o Content gerou de facto e no prefixo de URL
que cada uma serve.

::devtools-panel{tab="sources"}
::

## Colunas

| Coluna              | O que diz                                                       |
| :------------------ | :---------------------------------------------------------------- |
| `Prefix`            | O segmento de URL desta coleção; `/` para a que não tem prefixo    |
| `Collection`        | O nome de coleção gerado, tal como `queryCollection` o recebe, etiquetado com o seu tipo quando é uma secção gerada |
| `Repository`        | De onde vêm as páginas, com ligação quando é conhecido             |
| `Folder / artefact` | O `path` dentro desse repositório — uma pasta de documentação, ou o artefacto a partir do qual uma secção foi construída |
| `Ref`               | O ramo ou a etiqueta — e qual dos dois                             |
| `Version`           | O slug no URL, `default` na versão servida sem segmento próprio    |
| `Status`            | `current`, `deprecated` ou `eol`, directo da fonte                 |
| `Reserved segments` | Nomes de pasta desta fonte que um prefixo já reclamou              |

## Notas

**Um segmento de repositório só aparece a partir do segundo repositório**, e um de
versão só a partir da segunda ref — um segmento que só pode ter um valor não
distingue nada. `sourceOptions.showRepo` e `showVersion` forçam-nos na mesma.

**Os segmentos reservados são a armadilha para a qual esta coluna existe.** Se uma
fonte é servida em `/sdk` e a sua pasta de documentação contém um directório
`v1-9/`, o prefixo ganha e essa pasta fica inalcançável. O painel
[Checks](/reference/devtools/checks) comunica isso como erro; esta coluna mostra
que nomes estão tomados antes de acontecer.

**Uma secção gerada é uma coleção como qualquer outra**, que é o que permite ao
resto da camada trabalhar sobre ela sem alterações — e o que a tornava aqui
indistinguível de uma árvore de documentação cuja pasta calhava chamar-se
`CHANGELOG.md`. A etiqueta ao lado do nome da coleção é o seu tipo, para que as
linhas `changelog` e `openapi` se leiam como o que são, e o resumo as conte. O
que o próprio artefacto teve a dizer é um achado e não uma coluna, e é
comunicado no painel [Checks](/reference/devtools/checks).

O rodapé nomeia o ficheiro de onde a lista foi lida — útil num site cujo
`app.config.ts` não está onde esperavas.
