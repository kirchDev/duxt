Todas as chaves que o tema lê, com um emblema a dizer de onde vieram. «Porque é que
a entrada do duxt ainda está na minha barra de navegação?» custa aqui um olhar em
vez de uma sessão.

::devtools-panel{tab="config"}
::

## Os emblemas

| Emblema    | Significado                                                      |
| :--------- | :----------------------------------------------------------------- |
| `consumer` | O teu `app.config.ts` definiu-a                                    |
| `layer`    | É o valor por omissão da camada, intacto                           |
| `build`    | Foi calculada pela compilação e não está escrita em lado nenhum    |

## A regra de fusão

**Os arrays são substituídos por inteiro, os objectos fundem chave a chave.** A
`navigation` de um consumidor é a navegação — as entradas da camada desapareceram.
O seu `footer.note` deixa `footer.columns` em paz.

Não é o que o Nuxt faz com o `app.config` por si só: o defu concatena arrays, pelo
que um site teria as suas entradas mais as nossas, sem forma de retirar as nossas.
Por isso a camada não publica lista nenhuma no `app.config` e funde-as ela própria.

## Notas

**Os valores estruturados abrem.** Uma linha com um objecto ou uma lista mostra uma
contagem e uma pré-visualização de uma linha; um clique imprime o valor inteiro,
indentado. Continua na página enquanto está fechado, por isso o filtro encontra a
linha por qualquer cadeia lá dentro — incluindo uma única tradução de um rótulo.

`resolvedSources` é a única chave que ninguém escreve: é o manifesto que a
compilação calculou a partir de `sources`, e que todos os outros painéis deste
separador lêem.
