`redirectFrom` no frontmatter de uma página torna-se route rules, uma por cada
prefixo sob o qual a página é servida. Este painel relê essas regras **do servidor
em funcionamento** em vez de as recalcular: uma regra gerada e uma regra servida são
afirmações diferentes, e só a segunda redirecciona alguém.

::devtools-panel{tab="redirects"}
::

## Written by

Reler as regras significa ler as de todos os módulos, não só as da camada — o
`@nuxtjs/sitemap` acrescenta `/sitemap.xml` em qualquer site com mais do que um
sitemap. Por isso cada linha diz quem a escreveu:

| Emblema          | Significado                                                  |
| :--------------- | :------------------------------------------------------------- |
| `redirectFrom`   | Gerada pelo duxt a partir do frontmatter de uma página          |
| `another module` | A route rule de outra pessoa, servida pelo mesmo servidor       |

Nada numa route rule regista o seu autor, por isso a camada anota ao lado os
caminhos que gerou, e o painel marca os restantes.

## Notas

**Uma regra por prefixo.** Um URL antigo estava guardado sob exactamente um dos
segmentos de repositório, de versão e de idioma — e nada diz qual —, por isso todas
as combinações redireccionam.

Uma página que redirecciona para si própria é saltada em vez de servida: isso é um
ciclo, não um redireccionamento.

Mover uma página tem um guia próprio: [Mover uma página](/guides/move-a-page).
