Aquilo com que o Content ficou, um bloco por coleção. Este é o painel que responde
a «a minha página está sequer na compilação?» — e, mais vezes, a «porque é que esta
tem outro aspecto?».

::devtools-panel{tab="pages"}
::

## Colunas

| Coluna         | O que diz                                                          |
| :------------- | :------------------------------------------------------------------ |
| `Path`         | O URL, prefixo incluído — o que `queryCollection` guarda             |
| `Title`        | Do frontmatter; `missing` é um aviso, não um palpite                 |
| `Description`  | Se existe alguma; alimenta os cartões, a imagem OG e o llms.txt      |
| `Icon`         | O nome Iconify do frontmatter                                        |
| `Last updated` | Do histórico de git, não da data do ficheiro                         |
| `Contributors` | Quantas pessoas o histórico nomeia                                   |
| `File`         | Abre o ficheiro de origem no teu editor                              |

## Notas

**Uma coleção sem histórico nenhum** é normalmente uma fonte remota sem
`history: true`. O Content clona com `--depth 1`, portanto o checkout tem um único
commit e todas as páginas pareceriam escritas por quem cortou a ponta — a camada
prefere dados nenhuns a dados errados.

**A partir da segunda coleção está tudo fechado.** Um site com cinco versões tem
cinco tabelas quase idênticas, e as cinco abertas ninguém lê.

**O filtro aparece sobre tabelas com mais de doze linhas.** Esconde as linhas que
não correspondem em lado nenhum, conta as que ficam, e uma recarga traz tudo de
volta.

**Uma coleção vazia é uma constatação, não uma tabela vazia** — todos os URL sob
esse prefixo são um 404, e o painel di-lo onde as linhas teriam estado.
