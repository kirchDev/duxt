`@kirchdev/duxt-wiki` apresenta uma fonte como uma wiki em vez de documentação: o
artigo ocupa toda a largura, o índice passa para o texto e as páginas ligam-se
entre si pelo nome. As páginas continuam a ser Markdown no Git. A camada não
acrescenta editor no navegador, contas nem comentários. Vê-a em funcionamento na
[demo de wiki](https://duxt.app/demo/wiki).

## Adicionar a camada

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  extends: ['@kirchdev/duxt', '@kirchdev/duxt-wiki']
})
```

Depois, atribui a uma fonte o tipo de página `article`:

```ts [app/app.config.ts]
export default defineAppConfig({
  duxt: {
    sources: [
      { path: 'wiki', slug: 'wiki', pageType: 'article' }
    ]
  }
})
```

::callout{type="warning"}
A camada acrescenta colunas do Content, componentes e tipos de página, por isso a
instalação exige uma nova imagem da aplicação uma única vez. Depois disso, páginas,
aliases, categorias e novos campos de infobox são alterações de conteúdo. Podem
chegar a um servidor Node em execução através de
[bundles de conteúdo](/concepts/runtime-content-bundles).
::

## Tipos de página

O `pageType` de uma fonte aplica-se a todas as suas páginas. Uma página substitui-o
com `type` no seu frontmatter.

| Tipo             | Usado para                                                    |
| :--------------- | :------------------------------------------------------------ |
| `article`        | Uma página normal, com o índice depois do parágrafo inicial   |
| `category`       | Uma página que apresenta uma categoria e lista os seus membros |
| `disambiguation` | Uma página que encaminha um título partilhado para os seus vários significados |

A navegação à esquerda está desativada, porque uma wiki se lê através das suas
ligações. Volta a ativá-la para todo o site com `wiki: { sidebar: true }` em
`app.config.ts`.

## Ligar pelo nome

`[[Target]]` liga a uma página pelo seu título, por um dos seus aliases ou pelo seu
caminho. A ligação é resolvida quando a página é apresentada, por isso mudar o nome
de um destino não obriga a reescrever as páginas que apontam para ele.

```md
[[Crown Light]]
[[Crown Light|the outer beacon]]
[[Crown Light#History]]
[[guides/mooring]]
[[~/other-source/Harbour map]]
```

Os nomes ignoram maiúsculas e minúsculas. Uma ligação procura na sua própria fonte e
versão e, depois, nos idiomas de recurso dessa fonte. Um `~/` inicial sai
explicitamente desse âmbito. O código em linha e os blocos delimitados mantêm-se
literais.

Dá mais nomes a uma página com `aliases: [Outer Light]` no seu frontmatter. Quando
um nome corresponde a várias páginas, ganha uma página `disambiguation` com esse
título. Sem ela, a ligação fica vermelha e a compilação avisa, porque adivinhar
levaria os leitores à página errada.

## Ligações vermelhas e backlinks

Uma ligação para uma página que não existe é desenhada a vermelho e nunca faz falhar
a compilação. Abre a página `/wanted?title=…` da fonte, que explica que a página está
em falta e lista quem liga a ela. Numa forja reconhecida, essa página oferece uma
proposta pré-preenchida para criar o ficheiro, por isso a escrita continua a passar
pelo Git. Abrir `/wanted` sem título lista todas as páginas em falta.

Cada artigo termina com as páginas que ligam a ele. As transferências em Markdown
simples, o MCP e `llms-full.txt` recebem ligações normais, e um nome por resolver
passa a texto simples, por isso um leitor automático nunca vê `[[…]]`.

## Categorias e navboxes

Lista as categorias de uma página no seu frontmatter:

```md
---
title: Crown Light
categories: [Beacons]
---
```

As páginas de categoria ficam em `<source>/category/<name>`, e as `categories` da
própria página são as suas categorias superiores. Uma categoria com membros funciona
sem página própria. Escreve uma com `type: category` quando precisar de uma
introdução.

Uma navbox desenha uma categoria e as suas subcategorias como um bloco de ligações.
Só aparece onde a colocares:

```mdc
::navbox{category="Beacons"}
::
```

## Infoboxes e consultas

Coloca uma infobox no início do corpo do artigo, antes do parágrafo inicial. Num ecrã
largo flutua ao lado do texto e num telemóvel empilha-se acima dele.

```mdc
::infobox{title="Crown Light" image="/crown.svg" type="beacon"}
:::infobox-row{label="Status" key="status"}
Lit
:::
:::infobox-group{title="Visit" collapsed}
::::infobox-row{label="Base" key="base"}
[[Lumen Harbour]]
::::
:::
::
```

As linhas podem conter Markdown e wikilinks. A compilação também guarda o texto
simples de cada linha como dados da página, sob a sua `key` ou, se não tiver, sob a
sua etiqueta. Define uma `key` em qualquer linha cuja etiqueta esteja traduzida, para
que todos os idiomas guardem o mesmo campo.

`::query` lista páginas com base nesses dados, na fonte e versão atuais:

```mdc
::query{type="beacon" where="status=Lit" columns="title,base"}
::
```

`where` compara um único `key=value` como texto sensível a maiúsculas e minúsculas,
por isso `01` e `1` são diferentes. `columns` é `title` por predefinição, que liga à
página.

## Encontrar o que precisa de atenção

[`duxt report`](/reference/cli) acrescenta à sua saída as páginas pedidas, órfãs, sem
saída e sem categoria.

## Lista de verificação

- [ ] `@kirchdev/duxt-wiki` vem depois de `@kirchdev/duxt` em `extends`
- [ ] A fonte indica `pageType: 'article'`
- [ ] Foi construída uma nova imagem da aplicação depois de instalar a camada
- [ ] Os títulos partilhados por várias páginas têm uma página `disambiguation`
- [ ] As linhas com etiquetas traduzidas têm uma `key`
- [ ] `duxt report` não mostra nenhuma página pedida que pretendesses escrever
