Todos os erros que esta camada realmente teve foram silenciosos: uma coleção que
o Content descartou porque o nome não era um identificador JavaScript, uma
página que dava 404 porque uma ligação tinha envelhecido, uma navegação que
voltava vazia. Nenhum dos três disse nada — a compilação estava verde e o site
errado. Por isso correm quatro verificações depois da compilação, todas a ler a
mesma coisa: a cache de análise que o Content deixa para trás.

| Verificação                                   | Gravidade |
| :-------------------------------------------- | :-------- |
| Uma coleção sem páginas                        | erro      |
| Uma pasta em conflito com um segmento de URL   | erro      |
| Um `title` ou `description` em falta           | aviso     |
| Uma ligação interna ou âncora partida          | aviso     |

## Porque a gravidade não é uniforme

Um erro custa uma página que ninguém consegue alcançar e que nada no site
alguma vez explicaria — uma coleção vazia é um 404 em todas as páginas de uma
versão. Um aviso custa qualidade: a página continua a ser apresentada, e uma
fonte remota pode desatualizar-se entre um lançamento e o seguinte sem que isso
seja culpa desta compilação. Fazer a compilação falhar porque o repositório de
outra pessoa avançou tornaria uma compilação verde dependente de um terceiro.

## O que as verificações sabem e tu não

- **Uma colisão de pastas** só é um problema enquanto um prefixo está ativo. Uma
  pasta de documentação chamada `v2` está bem num site sem versões e é
  inalcançável num versionado, porque o prefixo ganha. A compilação sabe qual é
  o caso, e a mensagem nomeia o ficheiro e oferece a solução.
- **Uma ligação é resolvida como o tema a resolve.** Um caminho absoluto escrito
  numa página é relativo à fonte dessa mesma página, por isso é tentado primeiro
  sob o prefixo da fonte e depois nu. Um verificador que fizesse apenas a forma
  nua reportaria todas as ligações corretas de um site multirrepositório.
- **URL externos não são verificados.** Verificar um poria a rede dentro da
  compilação, e um servidor alheio inacessível não é razão para a tua
  documentação não ser publicada.

## Escreve as ligações como caminhos de documentação absolutos

`/concepts/sources`, não `../2.concepts/2.sources.md`. O prefixo sob o qual uma
página é servida é decidido na compilação, por isso escrever caminhos sem ele é
o que permite que o mesmo Markdown sirva `/guides/deploying` num site e
`/acme/v2.0.0/guides/deploying` noutro. É também a única forma que o verificador
de ligações vê.
