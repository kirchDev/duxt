---
title: Mover uma página
description: redirectFrom no frontmatter, transformado em regras de rota sob todos os prefixos.
icon: lucide:signpost
---

Uma página movida é a única ligação partida que um site de documentação cria
para si próprio. Põe o URL antigo no frontmatter da página nova, e o
redirecionamento sai no mesmo commit que a mudança.

## Passos

::steps
1. **Move o ficheiro** e muda-lhe o nome como pretendias.

2. **Lista os caminhos antigos na própria página**, sem prefixo nenhum:

   ```md [docs/3.guides/6.deploy-a-site.md]
   ---
   title: Implementar um site
   description: Onde um site duxt pode correr.
   redirectFrom:
     - /getting-started/deploy
     - /deployment
   ---
   ```

3. **Compila de novo.** A compilação transforma cada entrada em regras de rota —
   sob todos os prefixos de repositório, versão e locale em que a página é
   servida.

4. **Verifica um deles**, prefixo incluído, no site compilado.

::

## Porque o frontmatter é o sítio certo

A correção sempre viveu fora do site: uma regra do nginx, um ficheiro
`_redirects` do Netlify, uma lista da Cloudflare — escritos por quem implementa
o site e nunca por quem moveu a página. E só a camada o pode resolver de uma
vez, porque só o manifesto resolvido sabe que prefixos existem; quem escrevesse
as regras à mão teria de redescobrir todo o esquema página a página.

::callout{type="tip" title="Reordenar nunca precisa de um redirecionamento"}
O prefixo numérico é retirado do URL, por isso mudar `3.guides/` para
`4.guides/` não move nada. Só a parte depois do ponto é o URL.
::

## Lista de verificação

- [ ] Todos os caminhos antigos estão listados, escritos sem prefixo
- [ ] A compilação não reporta nenhuma ligação interna partida
- [ ] Um URL antigo também redireciona sob o prefixo de versão, não só nu
- [ ] Nada foi acrescentado à configuração do servidor web
